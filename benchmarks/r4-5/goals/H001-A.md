## Research budget

Research candidate budget for Phase A: **2,000,000 candidate evaluations exactly**, unless a valid certificate is found at the current search target and the algorithm naturally advances to another target. The global research counter still stops at exactly 2,000,000.

Wall-clock ceiling: **25 minutes** including implementation, tests, search, checkpoint serialization, documentation, commit and push.

Candidate-evaluation semantics must be defined before the research run and remain unchanged across Phase A/B.

Test/replay evaluations for unit tests and split-resume equivalence are outside the research budget and must be separately labeled.

## Search design requirements

The researcher may choose the search heuristic, but it must be exactly resumable. Requirements:

- deterministic from explicit config + state;
- portable machine-readable checkpoint, preferably JSON;
- explicitly implemented PRNG/state or equivalently documented deterministic generator;
- no opaque process-memory dependency;
- no hidden use of wall-clock time as randomness;
- global candidate index monotone across resume;
- state sufficient to continue at the next candidate without replaying Phase A research candidates.

If a known exact value, known construction, known target size, known critical graph, or known `R(4,5)` search strategy is recalled, record it in a notes-only commit BEFORE it influences target selection, initialization, stop conditions, or search code.

## Mandatory split/resume test

Before or alongside the real research run, implement a small deterministic test with fixed config and small `a,b` such that:

- uninterrupted run for `a+b` evaluations produces final semantic state `U`;
- run `a`, serialize, deserialize, run `b` produces final semantic state `R`;
- `U == R` for all semantic fields.

Save the test code, config, result, and list of excluded metadata fields if any.

This is not a substitute for Phase B; it verifies the serialization mechanism before the real handoff.
