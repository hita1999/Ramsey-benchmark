# R44-G001 — 固定予算で下界証明書を構成する

## 位置づけ

Stage 3最初の研究Goalでは、`R(4,4)` の正確な値を目標として与えない。

目的は、固定予算内で `K_4` も独立な4頂点集合も持たない具体的グラフを構成し、Gitだけで再現・検証・レビューできる下界証明書として保存することである。

Stage 2に続き、会話履歴なしのfresh sessionからGitだけで研究を開始できるかも評価する。

## 実行契約

- Goal ID: `R44-G001`
- Benchmark: `benchmarks/r4-4/problem.md`
- Stage 3 root: `ab5624e9c411afe50137875811c26b46ecf13551`
- Goal execution base: **研究開始時のmain HEADを `git rev-parse HEAD` で取得して `research-notes.md` に保存する。**
- Researcher: Codex
- 推奨model: `gpt-6-astra`
- 推奨reasoning effort: `high`
- 実際のmodel/effort: 研究開始前に記録する。取得不能なら `missing` とする。
- 会話履歴: **fresh session必須**
- 作業branch: `codex/r44-g001-lower-bound`
- push先: `git push -u origin HEAD:refs/heads/codex/r44-g001-lower-bound`
- `main` への直接push禁止。引数なしpush・force push禁止。

fresh sessionへ渡すのは、原則として対象repositoryとこのGoalファイルの場所だけとする。以前のRamsey研究会話や既知値をプロンプトへコピーしない。

## 数値予算

初回実験では次のいずれか早い方を上限とする。

- wall-clock研究時間: **30分**
- 探索候補評価数: **10,000,000**

探索コードを書く場合、候補評価1回の定義をコード・研究ノートに一意に固定する。
wall-clockは準備・実装・探索・検査・文書化・成果物commitを含むGoal全体と、純粋な探索時間を可能な範囲で分けて記録する。

利用可能なgoal/tokenカウンタ等があれば開始・途中・終了で保存する。これは新規生成token数や課金量と同一視しない。

## 研究課題

単純グラフ `G` で、

- `K_4` を含まない。
- 独立な4頂点集合を含まない。

という条件を満たす具体的グラフを探索せよ。

探索は小さい頂点数から増やしても、直接大きいグラフを構成してもよい。固定予算内で得られた **最大頂点数の証明書** を保存する。

ここで「最大」は今回の実行・予算内で発見した最大を意味する。全グラフ中の最大性、次の頂点数での不存在、Ramsey数の上界を意味しない。

正確な既知値を目標頂点数、停止条件、search horizonとして使ってはならない。

## 証明書とverifier

証明書は少なくとも頂点数と辺集合を機械可読形式で保存する。

certificate-only verifierは探索コードをimportせず、証明書だけから以下を完全検査する。

1. 頂点・辺形式が単純無向グラフとして正しい。
2. 全 `C(n,4)` 個の4頂点集合を列挙する。
3. 4頂点集合の6辺が全て存在する `K_4` が0個。
4. 4頂点集合の6辺が全て存在しない独立4集合が0個。
5. 検査件数・違反件数・valid判定を機械可読に保存する。

違反を見つけても全列挙件数の監査が必要なら早期終了しない設計を優先する。

## 許可する手段

- Python
- DFS / backtracking
- local search / hill climbing
- simulated annealing / tabu
- SAT / SMT
- symmetry breaking
- bitset / incremental scoring
- 数学的構成
- 複数方式の併用

ランダム性を使う場合はseedと再始動規則を固定・保存する。

## 禁止する情報・Discovery protocol

以下を検索・流用しない。

- Web、論文、書籍、OEIS、既知値データベース
- `R(4,4)` の既知値
- 既知のRamsey graph / critical graph / extremal graph
- reference implementation
- 既知証明の検索

研究開始後、正確な値、具体的な既知構成、特定の巡回/Paley等の構成、既知の上界証明方針、分類結果などを想起した場合は、**それを利用する前に**次を行う。

1. `research-notes.md` に想起した具体的内容を記録。
2. その変更だけを独立checkpoint commitとして保存。
3. Discoveryを `CONTAMINATED` にする。
4. 記憶の正しさを証拠、停止条件、探索目標、初期グラフとして扱わない。

想起がなかったと自己申告でき、情報制約・記録要件を満たした場合のみReviewerがCLEAN判定を検討できる。研究担当自身が記録不足からCLEANを推定しない。

## 必須成果物

Goal終了時に最低限、次をGitへ保存する。

1. 固定予算内で得られた最大頂点数の具体的証明書。
2. certificate-only deterministic verifier。
3. verifierのテスト。
4. 使用した探索・構成コード。
5. 再現コマンド。
6. 探索予算、候補評価数、停止理由、wall-clock。
7. model / effort / 利用可能なtoken等の計測。
8. 失敗した探索方向と残課題。
9. `research-notes.md` のClaim台帳・現在地。
10. `proof.md` の下界への論理的帰結。
11. fresh-session handoff評価。
12. PR用branchへ明示的にpushした記録。

コード・証明書・ログは `benchmarks/r4-4/` 配下に置く。

## Claimの扱い

証明書が完全検査された場合、少なくとも次を分離する。

- `R44-C001`: 保存証明書が `K_4` も独立4集合も持たない。
- `R44-C002`: C001の `n` 頂点証明書から `R(4,4) >= n+1`。

研究担当による完全証明後は数学的状態を `PROVEN` としてよいが、独立レビュー前は `UNREVIEWED`。

より大きい証明書を発見できなかったことは上界Claimにしない。

## Acceptance criteria

`R44-G001` を `SOLVED` としてよいのは次をすべて満たす場合。

- 非自明な回避グラフがGitに保存されている。
- verifierが全4頂点集合を検査し、`K_4=0`、独立4集合=0を示す。
- verifierが探索コードから独立して実行可能。
- verifierテストが保存されている。
- 探索・構成方法、seed、予算、停止理由、再現コマンドが保存されている。
- fresh sessionとGoal execution baseが記録されている。
- model/effortと利用可能な計測値が記録されている。
- Claimが二軸状態で記録されている。
- 既知情報を想起した場合、利用前checkpoint規約を守っている。
- 成果は専用branchへpushされ、mainへの直接pushをしていない。

証明書の頂点数が期待より小さくても、それだけでGoal失敗とはしない。固定予算内で監査可能な研究成果を作ることが主目的である。

## 終了分類

必ず次の1つを記録する。

- `SOLVED`
- `PARTIAL_PROGRESS`
- `EXHAUSTED_BUDGET`
- `BLOCKED`
- `NO_PROGRESS`

探索が予算切れでも、Acceptance criteriaを満たす証明書を保存した場合は、探索停止 `EXHAUSTED_BUDGET` とGoal終了 `SOLVED` を別に記録してよい。

## 独立Reviewerへの引継ぎ

Reviewerは少なくとも次を独立に確認する。

1. 証明書の頂点数・辺集合。
2. 全4集合に対する `K_4` 不存在。
3. 全4集合に対する独立4集合不存在。
4. 下界への論理的帰結。
5. verifierの完全性とテスト。
6. heuristic failureを最大性・上界に誤用していないこと。
7. contamination checkpointの時系列。
8. fresh-session handoffとbase。
9. model/effort/予算記録。
10. PR-only運用が守られたか。

Reviewerが補助計算を行う場合は、研究側と独立したコード、実行環境、コマンド、結果を保存し、実際の再実行成功と単なるコード保存を区別する。

判定後はproof・research-notes・verification・benchmark-summaryの現在状態を同じreview closureで同期する。
