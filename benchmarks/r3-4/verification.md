## 再現手順

リポジトリのルートで実行する。Python標準ライブラリのみを使用する。研究担当の記録環境は Python 3.9.6。

```sh
python3 benchmarks/r3-4/verify.py benchmarks/r3-4/certificate.json
python3 -m unittest discover -s benchmarks/r3-4 -p 'test_*.py' -v
python3 benchmarks/r3-4/search.py --budget 500000 --output /tmp/r3-4-reproduced.json
cmp benchmarks/r3-4/search-result.json /tmp/r3-4-reproduced.json
```

verifierの期待出力:

```json
{"lower_bound": 9, "n": 8, "quadruples_checked": 70, "red_edges": 10, "triples_checked": 56, "valid": true}
```

`certificate.json` は頂点数 `n` と赤い辺 `edges` のみを含む。
頂点は0からn−1、各辺は u<v とし、記載のない辺は青である。
verifierは形式、範囲、重複、自己ループを検査した後、全ての三頂点集合について赤3辺、全ての四頂点集合について青6辺を調べる。
全列挙のため禁止構造に見落としはない。違反または入力不正は終了コード1となる。
証明書の検証には探索結果ファイルや探索コードを必要としない。

テストは保存された証明書の受理、赤三角形・青K4の拒否、11種の不正入力の拒否を確認する。
探索の隣接ビット表現と検証器の辺集合表現は異なるが、同一担当による作成のため、それ自体は独立レビューとは扱わない。

## 探索コードの監査と限界

`search.py` は空グラフから、次の頂点の既存頂点への近傍を整数マスクの昇順で列挙する深さ優先探索である。
追加頂点の近傍に赤い辺がある場合、または非近傍に独立な三頂点集合がある場合に枝を棄却する。この条件は、新しく追加した頂点を含む赤三角形・青K4を正しく排除している。

レビュー側でも同じ50万候補の決定的探索ロジックを再実行し、`candidates_examined=500000`、`search_status=EXHAUSTED_BUDGET`、8頂点・10辺の同一証明書が得られることを確認した。

ただし探索木は完了していないため、この計算は最大性・上界・不存在の証拠ではない。PRもそのような主張をしておらず、この扱いは適切である。
