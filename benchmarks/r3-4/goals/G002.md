# G002 — R(3,4) の上界を自足的に証明する

## Goalの位置づけ

G001では、8頂点の具体的な回避彩色から `R(3,4) >= 9` が独立検証済みとなった。

G002では下界とは独立に、9頂点の任意の赤青彩色について禁止構造のいずれかが必ず現れることを証明し、`R(3,4) <= 9` を確立する。

このGoalの目的は既知の答えを再掲することではなく、Gitに保存された問題設定だけから、監査可能な上界証明を構築できるかを検証することである。

## 実行設定

- Goal ID: `G002`
- Benchmark: `benchmarks/r3-4/problem.md`
- 推奨実行モデル: Codex / GPT-6 Astra × high
- Base commit: 実行開始前に `git rev-parse HEAD` で取得し、`research-notes.md` に記録する。
- Source of truth: Git。過去のCodex会話履歴は前提にしない。

モデル・reasoning effortは研究効率の評価対象であるため、実際に使用した設定を必ず記録する。

## 研究課題

次の命題を証明せよ。

> 9頂点の任意の単純グラフ `G` について、`G` が三角形を含むか、または `G` の補グラフが `K4` を含む。

同値に、赤青2彩色された `K_9` には赤い三角形または青い `K4` が必ず存在することを示す。

この命題から `R(3,4) <= 9` を導く。

## 重要な制約

### 外部の既知解を検索しない

禁止するもの:

- Web検索
- 論文・書籍・OEIS・データベースの参照
- 既知の `R(3,4)` 証明を探すこと
- reference implementationや既存benchmarkから証明を取得すること

一般的なグラフ理論、組合せ論、鳩ノ巣原理、二重計数、次数評価、有限集合の基本事実などは利用してよい。

### 記憶している既知情報を証拠として使わない

既知値、既知補題、既知証明の方針を意図せず想起した場合は、利用前に `research-notes.md` の「既知情報による汚染」へ具体的に記録する。

想起そのものを隠してはならない。

既知情報を想起した場合でも数学的証明の構築は続行してよいが、Discovery評価では汚染として扱う。

### G001の下界証明を上界の根拠にしない

`certificate.json` やC001/C002は、G002の上界命題を証明する根拠ではない。

必要に応じて現在のbenchmark状態を把握するために読んでもよいが、上界証明は9頂点の任意のグラフに対する一般的議論だけで成立させる。

## 許可する研究手段

- 手計算による理論探索
- 次数・近傍・独立集合の解析
- 鳩ノ巣原理、二重計数、偶奇性、包含排除
- 補助補題の導出
- Python等による小規模な反例探索・式の検算・ケース確認
- SAT/SMT等による仮説形成や独立検算

ただし、補助計算から観察された規則をそのまま `PROVEN` にしてはならない。

## 最終証明に関する要件

原則として、人間可読な自足的証明を最終成果物とする。

補助定理を利用する場合、その定理が `problem.md` だけから自明でないなら、次のいずれかを満たすこと。

1. `proof.md` 内で証明する。
2. 新しいClaimとして明示し、自足的な証明と依存関係を保存する。

特に、別のRamsey数や非自明なグラフ理論の定理を利用する場合、「既知だから」とだけ書いて済ませてはならない。

## 必須成果物

Goal終了時には最低限、次をGitへ保存する。

1. `R(3,4) <= 9` を導く上界Claim。
2. 必要な補助Claimと、その依存関係。
3. `proof.md` に追記した人間可読な上界証明。
4. `research-notes.md` の更新。
5. 試したが失敗した方針、反証された補題候補、残ったギャップ。
6. 使用モデル・reasoning effort・可能ならwall-clock timeとtoken消費量。
7. 独立Reviewerが何を検証すべきかの具体的な項目。

計算コードを利用した場合は、再現可能な形で `benchmarks/r3-4/` 配下に保存する。

## Acceptance criteria

G002を `SOLVED` としてよいのは、次をすべて満たす場合だけである。

- 9頂点の任意のグラフを対象とする議論になっている。
- 全ケースが尽くされている。
- `R(3,4) <= 9` が論理的に導かれている。
- 補助補題の証明が欠落していない。
- WLOG・対称性・次数条件などの利用が正当化されている。
- 計算上の観察を暗黙に証明へ昇格していない。
- `proof.md` 単独で主要な証明を追える。
- `research-notes.md` にGoalの終了状態と研究状態が保存されている。

独立レビューはG002完了後に別途行うため、G002終了時点では `PROVEN` と `INDEPENDENTLY_VERIFIED` を混同しない。

## 予算方針

これはStage 1の小規模な理論Goalである。

- まず短い理論証明を優先する。
- 大規模な全彩色探索を第一選択にしない。
- 行き詰まった場合のみ、小規模計算を仮説形成に使う。
- 残り予算が少なくなったら、未完成の証明を無理に閉じず、現在の補題・障害・次の一手をGitへcheckpointする。

## 終了分類

終了時に必ず次の1つを記録する。

- `SOLVED`
- `PARTIAL_PROGRESS`
- `EXHAUSTED_BUDGET`
- `BLOCKED`
- `NO_PROGRESS`

`EXHAUSTED_BUDGET` は数学的成功を意味しない。

## 独立レビューで重点確認する項目

G002完了後のReviewerは少なくとも次を監査する。

1. 9頂点の全グラフを本当にカバーしているか。
2. 次数や近傍に関する境界が正しいか。
3. 補助Ramsey命題等を使う場合、その証明が完全か。
4. 偶奇性・整数性・端点ケースに抜けがないか。
5. 必要条件を十分条件として扱っていないか。
6. Claim間に循環依存がないか。
7. 計算を使った部分がある場合、その役割が証明・観察・検算のどれか明確か。
8. G001で想起した既知値や既知構成が、上界証明の根拠へ混入していないか。
